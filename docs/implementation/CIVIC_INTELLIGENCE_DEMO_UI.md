# Civic Intelligence Demo UI

## 1. Overview

The Civic Intelligence Demo UI (implemented in `DemoPanel.tsx`) provides a frontend harness for executing controlled synthetic scenarios without affecting the production database, executing live Gemini requests, or exposing PII. It bridges the gap between the `POST /api/demo/scenarios/run` backend contract and the policymaker dashboard.

## 2. UI Entry Point

The Demo Panel is embedded directly into the primary Dashboard layout (`page.tsx`), sitting directly above the `AnalyticsOverview`. This allows users to conceptualize the demo as an active workflow injection rather than an isolated playground.

The entry point clearly labels the context:
- `SYNTHETIC DEMO`
- `AI MODE: DEMO / DETERMINISTIC MOCK`

## 3. Scenario Catalog

The UI rigidly enforces a subset of allowed execution vectors via a disabled-by-default `<select>` dropdown. Arbitrary ID injection is structurally impossible from the React component.

**Allowed Scenarios:**
- **Water Convergence:** End-to-end matching of water needs with JJM footprint.
- **Water (No Public Gap):** Demand exists, but infrastructure is reported as complete.
- **Non-Water Demand:** Civic needs outside the currently supported JJM taxonomy.
- **Unresolved Geography:** Signals that lack identifiable LGD codes.

## 4. Pipeline Visualization

When a scenario is executed, the resulting pipeline summary counts are rendered in a vertical timeline visualization. It maps:
1. Citizen Signal
2. Civic Need
3. Citizen Demand
4. Unmet Demand
5. Convergence
6. Priority
7. Evidence Ledger

A stage is visually marked as active/successful only if its count is > 0.

## 5. Strict Provenance Distinctions

The API contract demands explicit provenance handling. The UI enforces this by rendering distinct badges:
- **SYNTHETIC DEMO SIGNAL** (for citizen evidence)
- **REAL / OFFICIAL JJM/LGD** (for public evidence)

These are never collapsed into a generic "Verified" state.

## 6. Zero Math & PII Boundaries

The UI is entirely declarative. It does not:
- Calculate priority scores
- Count signals or aggregate demand
- Execute API calls to Gemini
- Render pseudonyms or raw citizen text

If the pipeline resolves without a priority score (e.g. `WATER_NO_PUBLIC_GAP`), the UI explicitly renders "No combined priority score available" rather than a misleading `0.0`.

## 7. Evidence Ledger Drill-Down

If the scenario generates Priority Assessments and Evidence Ledger entries, the UI exposes an **"Inspect Evidence"** action. Following strict design constraints to avoid UI duplication, this button prompts the user to utilize the existing `VillageLookup` or `HotspotMap` components below it to drill into the specific village generated by the scenario (e.g. `275084`). This forces the user to experience the authentic policymaker workflow.
